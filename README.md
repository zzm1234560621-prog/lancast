# LanCast · 手机直接操作电脑的内网投屏

把 Windows 电脑的屏幕实时投到同一局域网里的手机、iPad、安卓平板或另一台电脑上，并让手机直接当**触控板、键盘、手柄和自定义按键面板**操作电脑。**观看端只需要浏览器**（iOS / iPadOS Safari、Android Chrome、任意桌面浏览器），不用安装 App。

- **手机操作电脑（主推）**：触控板式鼠标、直接点按、双指滚动、缩放；屏幕按键映射（按住/切换/点按、组合键、虚拟摇杆、导入导出）；蓝牙手柄映射；中文输入法。默认只能看，必须在电脑管理页逐个设备授权“允许控制”。
- **低延迟**：H.264 零延迟编码 + 浏览器 WebCodecs 解码，始终只显示最新一帧；网络变差时直接丢弃积压帧，跳到下一个关键帧追上。本机 1080p60 实测“采集→送达”中位数 **8.9 ms**，手机端到端约 **12–15 ms**。
- **CPU / GPU 双管线**：CPU 软件编码（libx264）与 GPU 硬件编码（QSV / Media Foundation / NVENC / AMF）都可用；首次启动自动测速选最快，也可手动指定，见下文“两条编码管线”。
- **自动选最优**：首次启动自动测速本机可用的 H.264 编码器，按实际耗时选最快方案并缓存，不用用户手调。
- **加密**：全程 TLS（优先 1.3，仅前向保密套件）。自带名称受约束的本地 CA，可选安装到手机，之后不再有证书警告。
- **安全**：一次性 PIN / 二维码配对，新设备需电脑端点“允许”；设备令牌可随时撤销；只接受私网来源；管理界面只在本机可访问。详见 [docs/SECURITY.md](docs/SECURITY.md)。
- **多设备**：默认最多 8 台同时观看。每台可以看不同的显示器；同一显示器的画面只编码一次，再分发给所有观看者。
- **每台设备自选画质**：省流 / 流畅 / 标准 / 高清 / 原画 / 自定义（分辨率、帧率、码率），另有按网络状况自动升降的“自动”档。
- **兼容**：不支持 WebCodecs 的旧设备（iOS 16.4 以前等）自动改用 JPEG 兼容模式。
- **好用**：扫码即连、记住设备、双指缩放平移、显示鼠标指针、统计浮层（帧率 / 码率 / RTT / 端到端延迟）、屏幕常亮、断线自动重连，可“添加到主屏幕”全屏使用。

## 快速开始

**方式一：Windows 安装包（推荐）**

下载 [最新 Release](https://github.com/zzm1234560621-prog/lancast/releases/latest) 里的 `LanCast-*-win64.zip`，解压后运行 `LanCast.exe`。不需要 Python。

**方式二：源码运行**

```powershell
git clone https://github.com/zzm1234560621-prog/lancast.git
cd lancast
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python -m lancast
```

完整的安装、防火墙、开机自启、升级和卸载步骤见 [docs/DEPLOY.md](docs/DEPLOY.md)。

启动后：

1. 控制台会打印二维码、6 位配对码，并自动在浏览器里打开**本机管理页面**。
2. 手机连上和电脑**同一个 Wi-Fi**，用相机扫二维码（或在浏览器里输入控制台显示的 `https://192.168.x.x:8443`，再填配对码）。
3. 首次打开会提示证书不受信任，这是正常的（证书是这台电脑自己签发的）：
   - iPhone / iPad：点“显示详细信息” →“访问此网站” → 再确认一次。
   - Android Chrome：点“高级” →“继续前往”。
4. 在电脑的管理页面点**允许**，画面就出来了。
5. 默认勾选了“记住此设备”，以后打开同一地址会自动连上，不用再配对。

## 两条编码管线

LanCast 有两条可选的编码路径，首次启动会自动测速，用户不用手选；也可以手动强制：

| 管线 | 后端 | 特点 | 手动指定 |
|---|---|---|---|
| **CPU 管线** | `libx264` + 线性缩放 | 兼容性最好；本机 1080p60 采集→送达 p50 **8.9 ms** | `--encoder libx264` |
| **GPU 硬件管线** | `h264_qsv` / `h264_mf` / `h264_nvenc` / `h264_amf` | 编码交给核显/独显，CPU 占用低；不同机器快慢不同 | `--encoder h264_qsv` 等 |

默认 `--encoder auto`：启动时用合成动态画面分别实测两条管线在本机的速度，选最快并缓存。也可以用 `--retune` 重新测速。

这台测试机（Intel Core Ultra 9 185H + Arc 核显）的结果是：

```
libx264 = 7.33 ms/帧
h264_qsv = 23.15 ms/帧
→ 自动选择 CPU 管线
```

所以“有核显就一定用核显”并不成立；在 NVIDIA/AMD 机器上 `h264_nvenc` / `h264_amf` 会参与实测，可能胜出。

> **GPU 零拷贝实验**：`ddagrab → hwmap qsv → scale_qsv → h264_qsv` 的完全零拷贝管线已在实验室跑通，但这代 Intel Arc 上约 12.5 ms/帧，比 CPU 管线慢，所以没有放进默认候选。真正要再往下压，需要原生 Media Foundation / oneVPL helper；目前发布版提供的是上表中的 GPU 硬件编码管线，不是“零拷贝”。

## ⚠ Windows 防火墙（手机连不上时先看这里）

首次启动时，Windows 会弹窗询问是否允许 Python（或 LanCast.exe）通信，请点允许。

如果 LanCast 启动时提示 **“当前网络被 Windows 标记为公用网络”**，防火墙默认会挡住手机。二选一：

- **推荐**：设置 → 网络和 Internet → WLAN → 当前连接的网络 → 网络配置文件类型，改为 **专用网络**。
- 或者用**管理员身份**打开 PowerShell，只放行本机子网访问 8443 端口：

  ```powershell
  New-NetFirewallRule -DisplayName "LanCast" -Direction Inbound -Protocol TCP -LocalPort 8443 -Action Allow -Profile Private,Public -RemoteAddress LocalSubnet
  ```

一键检查环境（显示器、采集、编码器、网络、端口、证书）：

```powershell
.venv\Scripts\python -m lancast doctor
```

## 消除证书警告（可选，推荐）

在手机上安装 LanCast 的本地 CA 后，就不会再看到警告，同时也能防中间人攻击。这个 CA 带名称约束，只对私网地址有效，**无法被用来冒充任何公网网站**。

1. 在手机浏览器打开 `https://<电脑IP>:8443/ca.crt`（配对页底部“证书说明”里也有链接）。
2. **iPhone / iPad**：允许下载描述文件 → 设置 → 通用 → VPN 与设备管理 → 安装“LanCast Local CA” → 再到 设置 → 通用 → 关于本机 → 证书信任设置，打开它的“完全信任”。
3. **Android**：设置 → 安全 → 加密与凭据 → 安装证书 → CA 证书 → 选择下载的 `LanCast-CA.crt`。
4. 想更放心的话，可以把手机上显示的证书指纹，与电脑管理页“安全信息”里的 CA 指纹对一下。请只在你信任的网络上做这一步。

## 用手机操作电脑（可选）

默认只能看。要用手机操作电脑，先在电脑上授权：新设备请求连接时点“允许控制”，或在管理页给已连接 / 已记住的设备打开“允许控制”开关。管理页的“允许远程控制”是总开关；有设备正在操作时，顶部会显示“远程控制中”，并提供“停止所有控制”按钮。

授权后，在手机工具栏的“控制模式”里选：

| 模式 | 操作 |
|---|---|
| 仅观看 | 默认，只能缩放和平移画面 |
| 触控板 | 单指拖动 = 移动鼠标；单指轻点 = 左键；双指轻点 = 右键；三指轻点 = 中键；轻点后马上按住拖动 = 左键拖拽；双指拖动 = 滚轮；双指捏合 = 缩放画面 |
| 直接点按 | 点哪里就点击哪里；长按 = 右键；按住拖动 = 拖拽；双指拖动 = 滚轮 |

- **灵敏度**（设置 → 控制）：指针灵敏度 0.2–5、指针加速、滚动速度、自然滚动方向、虚拟摇杆和手柄摇杆的灵敏度与死区。设置保存在手机浏览器里。
- **按键映射**：工具栏“按键”可以显示屏幕按钮。“编辑布局”可以拖动摆放、添加按钮或摇杆，给按钮绑定任意按键或组合键，以及鼠标左 / 右 / 中键、滚轮。按钮有“按住”“切换”“点按”三种模式；摇杆可以映射为 WASD、方向键或鼠标移动。内置“游戏 WASD”“PPT 演示”“媒体”“常用快捷键”四套布局，可以新建、导出、导入。
- **手柄**：给手机连上蓝牙手柄后，设置里会出现“手柄”分区，可以把各个按键和摇杆映射到键盘或鼠标。
- **打字**：工具栏“键盘”调出手机输入法，支持中文。
- 安全：服务端会逐个检查收到的事件；手机断线、权限被收回或按住键超过 3 秒没有消息时，会自动松开所有按键。详见 [docs/SECURITY.md](docs/SECURITY.md)。

注意：LanCast 以普通权限运行时，Windows 不允许它操作“以管理员身份运行”的窗口（如 UAC 提示）。

## 画质

手机设置里的“画质”可以为这台设备单独选择：

| 档位 | H.264 | 适合 |
|---|---|---|
| 省流 | 960×540 · 30fps · 2 Mbps | 信号差、流量有限 |
| 流畅 | 1280×720 · 60fps · 5 Mbps | 手机、Wi-Fi 一般 |
| 标准（默认） | 跟随电脑端设置（默认 1920×1080 · 60fps · 10 Mbps） | 大多数情况 |
| 高清 | 2560×1440 · 60fps · 20 Mbps | iPad、5 GHz Wi-Fi |
| 原画 | 不缩放 · 60fps · 35 Mbps | 看细小文字 |
| 自定义 | 自选分辨率、帧率（15–240）、码率（1–200 Mbps） | 帧率和码率不会超过电脑端设置与“原画”档两者中的较高值（默认 60fps / 35 Mbps），电脑端调高后上限随之提高 |
| 自动 | 从“标准”起步，卡顿或延迟高就降档，稳定 30 秒后回升 | |

选择相同画质的设备共用一个编码器；每块屏幕最多同时跑 4 种画质，超出时会自动并入最接近的一种。界面上显示的是电脑端**实际生效**的值。电脑端可以在管理页关掉“允许观看端自选画质”，这样所有设备都使用“标准”档。

手机设置里还有两档一键模式：

- **低延迟模式**：1080p60 / 10 Mbps，日常推荐。
- **极限模式**：1080p60 / 10 Mbps，发送队列从 2 帧降到 1 帧，并关闭远程光标消息。适合同一房间、5 GHz、网络稳定时；弱网下会更容易丢帧和请求关键帧。

## 管理页面

启动时会自动打开（地址也打印在控制台，形如 `http://127.0.0.1:8442/admin#token=…`，只能在本机访问）：

- **连接设备**：二维码、主地址和其他网卡地址、配对码（带倒计时，可手动更换）。
- **待批准请求**：新设备在这里点“允许 / 拒绝”。有请求时标签页标题会提示，并响一声。
- **正在观看**：每台设备的显示器、模式、帧率、码率、RTT、端到端延迟、丢帧，可以单独断开。
- **已记住的设备**：可撤销，撤销后对方立即断开，下次需要重新配对。
- **共享设置**：帧率、最大分辨率、码率、JPEG 质量 / 帧率、是否需要批准，改完立即生效。
- **暂停共享**、安全信息（证书指纹、CA 下载）、事件日志。

## 自动测速

第一次在这台电脑上启动时，LanCast 会用一段合成画面分别跑一遍可用的 H.264 编码器（libx264、QSV、Media Foundation、NVENC、AMF 等），按 1080p 的实际编码耗时选中最快的一个，结果缓存在数据目录的 `autotune.json`，以后启动直接复用。机器换了或想重新比较，加 `--retune` 启动一次即可；也可以用 `--encoder` 手动指定。

## 常用参数

```powershell
.venv\Scripts\python -m lancast [选项]
```

| 选项 | 默认 | 说明 |
|---|---|---|
| `--port` | 8443 | 局域网 HTTPS 端口 |
| `--admin-port` | 8442 | 本机管理页端口 |
| `--fps` | 60 | H.264 帧率上限 |
| `--max-res` | 1080p | 输出分辨率上限：`720p` `1080p` `1440p` `4k` `native` 或 `1920x1080` |
| `--bitrate` | 10M | H.264 码率，如 `6M`、`15000k` |
| `--encoder` | auto | 首次启动自动测速选择（libx264 / h264_qsv / h264_mf / nvenc / amf），也可手动指定 |
| `--retune` | 关 | 强制重新测速并重新选择编码器 |
| `--jpeg-quality` / `--jpeg-fps` | 70 / 15 | 兼容模式的画质与帧率 |
| `--no-approval` | 关 | 新设备配对后无需在电脑上点允许 |
| `--no-control` | 关 | 启动时关闭远程控制总开关（之后可在管理页打开） |
| `--fake-input` | 关 | 测试用：远程输入只记录、不执行 |
| `--max-viewers` | 8 | 同时观看的设备上限 |
| `--allow-cidr` | — | 额外放行的来源网段，如 `100.64.0.0/10`（Tailscale） |
| `--pin-ttl` | 600 | 配对码有效期（秒） |
| `--no-open` | 关 | 启动时不自动打开管理页 |
| `--capture` | auto | `dxgi` / `mss` / `synthetic`（测试图案，不采集真实屏幕） |

其他命令：`python -m lancast doctor`（环境检查）、`python -m lancast devices [--revoke ID | --revoke-all]`（管理已记住的设备）。

观看端：轻触画面显示工具栏，可切换显示器、模式（流畅 H.264 / 兼容 JPEG）、适应 / 填充、统计、全屏；双指缩放、放大后拖动、双击切换缩放。电脑上用浏览器看时，`f` 键全屏，`s` 键显示统计。

## 性能（本机实测）

测试机：Intel Core Ultra 9 185H + Intel Arc 核显，屏幕 2880×1800 @ 120Hz。服务端与客户端在同一台机器上，用同一个高精度时钟测量“采集完成 → 客户端收到”：

| 输出档位 | 采集→送达 p50 | p95 |
|---|---:|---:|
| **1080p60（低延迟模式）** | **8.9 ms** | **14.0 ms** |
| 1080p120 | 9.9 ms | 24.7 ms |
| 720p120 | 9.0 ms | 10.4 ms |
| 原生 2880×1800 @ 60 | 13.9 ms | 24.4 ms |

关键优化：1080p 缩放从 `INTER_AREA` 改为线性插值（单帧 7.7 ms → 2.1 ms）；H.264 解码后立即绘制，不等下一次 `requestAnimationFrame`；服务端发送队列最多 2 帧。1080p60 比 1080p120 更快，是因为编码耗时翻倍，所以“低延迟模式”固定 1080p60。

完整端到端还要加：手机硬件解码 3–6 ms、屏幕刷新最多 1 帧、Wi-Fi 1–3 ms，所以局域网里大约 **12–15 ms**（视手机和网络）。

自动测速会分别实测本机可用编码器。这台机器上：

```
libx264 = 7.33 ms/帧
h264_qsv = 23.15 ms/帧
→ 选择 libx264
```

所以不是“有核显就一定用核显”；在 NVIDIA/AMD 机器上 NVENC/AMF 会参与实测，可能胜出。GPU 零拷贝的 FFmpeg QSV 管线也验证过，但这代 Intel Arc 上反而更慢（约 12.5 ms/帧），因此没有放进默认链路。

自己测量：

```powershell
.venv\Scripts\python scripts\measure_latency.py --synthetic 2880x1800
.venv\Scripts\python scripts\measure_latency.py --encoder libx264 --max-res 1080p --fps 60
```

## 常见问题

- **手机打不开页面**：先看上面的“Windows 防火墙”一节；确认手机和电脑在同一网络（访客网络或开了“AP 隔离”的路由器会互相隔断）；IP 不对时，到管理页“其他地址”里换一个。
- **页面能打开，但一直“正在连接”**：部分 iOS 版本即使在页面上点了“继续访问”，WebSocket 连接仍然不认这个证书。按上面“消除证书警告”的步骤安装本地 CA 即可解决。
- **一直转圈 / 黑屏**：在工具栏切到“兼容 JPEG”试试；iOS 16.4 以前的系统不支持 WebCodecs，会自动改用 JPEG。
- **卡顿或延迟高**：用 5 GHz Wi-Fi；在管理页降低分辨率、码率或帧率；看统计浮层里的 RTT 是否偏高。
- **电脑 IP 变了以后要重新配对**：浏览器按“地址”保存记住的设备，IP 变了就算新地址。建议在路由器里给电脑固定 IP。
- **端口被占用**：`--port 9443 --admin-port 9442`。
- **想把 iPad 当扩展屏**：先给 Windows 装一个虚拟显示器驱动，它会成为一个普通显示器，在观看端切换过去即可。

## 已知限制

- 被投屏端只支持 Windows 10 / 11（采集用 DXGI，失败时退回 GDI）；观看端不限平台。
- 不传声音。
- 远程控制在 Windows 上通过 SendInput 实现，无法操作以管理员身份运行的窗口；少数使用反作弊或直接读取硬件输入的游戏可能不响应。
- UAC 提示和锁屏属于安全桌面，采集不到。

- 验证打包结果：`powershell -ExecutionPolicy Bypass -File packaging\verify.ps1 -Exe packaging\dist\LanCast\LanCast.exe`（用测试图案启动 exe，检查各页面，并完成一次配对和收流）
