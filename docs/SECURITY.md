# LanCast 安全说明

LanCast 会把你电脑屏幕上的一切发到网络上，所以它默认按“同一局域网里可能有不怀好意的人”来设计。本文说明它防什么、怎么防，以及**防不住什么**。

## 1. 防护目标

| 威胁 | 例子 |
|---|---|
| 同网段的陌生人想看你的屏幕 | 合租、宿舍、公司、咖啡店 Wi-Fi 上的其他设备 |
| 被动窃听 | 同一 Wi-Fi 下抓包 |
| 通过你的浏览器攻击本机服务 | 恶意网页发起 CSRF、跨站 WebSocket 劫持、DNS 重绑定 |
| 服务被意外暴露到公网 | 路由器端口转发、UPnP、VPN 网段 |
| 恶意客户端打垮服务 | 消息洪泛、超大消息、畸形数据、暴力猜 PIN |
| 未经授权操作你的电脑 | 只有观看权限的设备试图发送鼠标、键盘事件 |

## 2. 防护机制

### 传输加密
- 局域网端口只提供 **HTTPS / WSS**：TLS 1.2 起步，优先 TLS 1.3；TLS 1.2 只允许 ECDHE + AEAD 套件（前向保密），禁用压缩与重协商。
- 画面、鼠标指针、控制消息全部走同一条加密的 WebSocket。

### 本地证书颁发机构（CA）
- 首次运行时在 `%LOCALAPPDATA%\LanCast` 生成一个 ECDSA P-256 根证书和服务器证书。服务器证书覆盖本机全部私网 IP、`localhost` 和 `<主机名>.local`。IP 变化或证书临近过期时会自动重签。
- 根证书带 **critical 名称约束（Name Constraints）**，只允许签发私网 / 回环 / 链路本地 / CGNAT 地址和 `localhost`、`*.local` 名称。即使私钥泄露，也**无法用它冒充任何公网网站**。所以在手机上安装并信任它的风险是可控的。
- 私钥文件放在当前 Windows 用户的私有目录里，默认只有你自己的账户能读。

### 配对与身份
- **一次性配对码**：6 位数字，用一次即作废；10 分钟过期；累计输错 5 次自动更换。
- **二维码令牌**：128 位随机值，与 PIN 同步轮换。它放在 URL 的 `#` 片段里，不会出现在 HTTP 请求行、服务器日志或 Referer 中。页面读取后会立刻把它从地址栏抹掉。
- **限速**：同一来源 IP 在 5 分钟内认证失败 5 次，会被封禁 5 分钟。
- **电脑端批准**（默认开启）：新设备即使配对码正确，也要你在本机管理页点“允许”，60 秒内不处理视为拒绝。
- **记住设备**：配对成功后可颁发 256 位设备令牌。服务端只存它的 SHA-256 摘要，校验用常数时间比较。在管理页可随时撤销，撤销会立即断开该设备。

### 网络边界
- 局域网端口只接受**私网、回环、链路本地**来源，其余一律拒绝，以防路由器把端口误转发到公网。确实需要时可用 `--allow-cidr` 显式放行，例如 Tailscale 的 `100.64.0.0/10`。
- **管理界面只监听 `127.0.0.1`**，局域网端口上根本没有管理接口。

### 管理接口（本机）
- 每次启动随机生成管理令牌，必须放在自定义请求头 `X-Admin-Token` 里。跨站请求带这种头需要 CORS 预检，而服务端从不放行，所以 CSRF 无法得逞。
- 校验 `Host` 头，只接受 `127.0.0.1` / `localhost` / `[::1]` 加上管理端口，以防 DNS 重绑定。
- 写操作只接受 `application/json`，并检查 `Origin`。

### WebSocket
- `Origin` 必须与页面同源，以防跨站 WebSocket 劫持。
- 连接后 10 秒内必须完成认证；未认证前收不到任何画面。
- 单条消息最大 8 KiB；每个连接限速 20 条/秒（允许突发 40 条）；客户端发来二进制帧直接断开；同时观看的设备默认最多 8 台。
- 不启用 WebSocket 压缩（避免压缩相关的侧信道和额外 CPU 开销）。

### 远程控制（手机操作电脑）
- **默认只能观看。** 控制权限必须由你在电脑上逐个设备授予：批准新设备时选“允许控制”，或之后在管理页打开该设备的“允许控制”开关。记住的设备会保存这项授权，随时可以收回。
- **总开关**：管理页“允许远程控制”一关，所有设备立即失去控制权。“暂停共享”也会同时暂停控制。有设备正在操作时，管理页顶部会醒目提示，并提供“停止所有控制”按钮。
- **服务端逐个事件校验**，手机端的检查不作数：
  - 键码只接受白名单内的 127 个，鼠标键只有 5 种。
  - 单次移动、滚轮、文字长度都有上限。
  - 每台设备每秒最多 120 条输入消息、2000 个字符。
  - 持续超限会被断开。
- **防卡键**：手机按住键期间每秒发一次心跳；服务端 3 秒收不到任何输入，就自动松开这台设备按住的所有键和鼠标键。断线、收回权限、暂停、切换显示器时也会全部松开。
- **不记录按键内容**：日志只写“某设备正在远程控制”，绝不记录具体按了什么、输入了什么（可能是密码）。
- 测试图案模式（`--capture synthetic`）和 `--fake-input` 下，输入只被记录、不会真正执行。

### 网页
- 严格 CSP：禁止内联脚本和样式，禁止被嵌入 iframe（`frame-ancestors 'none'`），只连接同源。另有 `nosniff`、`no-referrer`、COOP/CORP。
- 静态文件在启动时一次性读入内存并按文件名查表，不存在路径穿越。
- 远程设备上报的名称会先去掉控制字符和双向覆盖字符；管理页一律按纯文本渲染，杜绝 XSS。
- PIN 和各类令牌不会写入事件日志。

## 3. 已知局限

1. **自签名证书下的主动中间人**：如果没安装本地 CA，首次访问时浏览器无法核实服务器身份。同一网络里能做 ARP 欺骗的攻击者，理论上可以在你点“继续访问”时冒充电脑。网页代码本身也来自服务器，浏览器端的任何额外加密都补不上这个洞。
   **解决办法**：在手机上安装并信任 LanCast 本地 CA（见 README），或核对证书指纹。被动窃听始终防得住，不受此影响。
2. **投出去的就是屏幕上的一切**，包括弹出的通知、聊天、密码管理器窗口。需要时用管理页的“暂停共享”。
3. **授予“允许控制”，就等于把键盘鼠标交给那台设备。** 它能做你坐在电脑前能做的一切，包括打开本机管理页、给其他设备授权。只授权你自己的设备；用完可以收回，或直接关掉总开关。
4. Windows 的 UIPI 机制会阻止普通权限的程序操作“以管理员身份运行”的窗口（如 UAC 提示、部分系统工具），所以 LanCast 正常运行时控制不了这些窗口。不建议为此以管理员身份运行 LanCast，那样会放大风险。
5. 本机安全以 Windows 账户为界：能以你的身份在本机运行代码的程序，可以读取私钥、管理令牌和屏幕内容，这不在本工具的防护范围内。
6. UAC 提示和锁屏属于“安全桌面”，DXGI 采集不到，这是 Windows 的保护机制。

## 4. 使用建议

- 把家里的 Wi-Fi 设成“专用网络”，不要在公共 Wi-Fi 上开启投屏。
- 安装本地 CA（一次即可），之后既没有警告，又能防中间人。
- 不用时按 Ctrl+C 关掉服务；在管理页撤销不再使用的设备。
- 别把 LanCast 的端口转发到公网。需要远程观看时，用 Tailscale / ZeroTier 这类加密组网，再加 `--allow-cidr`。
